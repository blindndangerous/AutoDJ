# Screen-reader sample for 0.21.0

This is the pre-release sample for AutoDJ 0.21.0, taken on 2026-10-14 on the release branch at
b895fdef, with the fix for D1 applied (the fix is in the commit that adds this record). It covers
the flows listed under "Release sampling" in [Accessibility testing](../accessibility-testing.md)
with NVDA and Chrome, and a subset of them with NVDA and Edge and with NVDA and Firefox. The results
apply only to the pairings, flows and steps described below.

## What 0.21.0 ships with

- One release blocker was found and fixed before release: in Chrome, with and without
  JavaScript, the listener request page could not send a request. Send request answered with the
  raw text `{"detail":"Disallowed Origin"}` (D1). After the fix, requests were sent and answered
  in Chrome, Edge and Firefox.
- New in 0.21.0 and confirmed by NVDA speech: the listener request page and the operator's Listener
  requests card; the player page and the embeddable player, also inside a titled frame on another
  site; the public status page with and without JavaScript; several stations and Settings,
  Stations; DMCA mode; Categories and Category conditions in Clockwheels; the clockwheel step
  list's keys; Shows; Track landmarks and the bracket keys; the Hour preview; More formats and
  Listener statistics; the Track info tab with its Tags editor and its unsaved-tags dialog; the
  webhook list and Send test; and the "AutoDJ still cannot be reached" notice.
- Seventeen other defects, none of them a blocker; D2 to D7 are moderate and the rest minor. The
  moderate ones:
  - D2: a status message that is the same as the one before it is not spoken again.
  - D3: Listen here stops when the page's connection drops and does not start again.
  - D4: a failed clockwheel refresh is spoken every 5 seconds while AutoDJ is out of reach.
  - D5: deleting a category says no clockwheel uses it when one does.
  - D6: in the History and Hour preview tables, moving down a column other than the song's says
    only that cell, not which song the row is.
  - D7: after Save show, NVDA reads the whole Shows card.
- Carried over and still accepted: the pairing dialog's name and instructions are spoken twice
  when it opens (0.18.0 D4), now heard in all three browsers and when a session ends, and NVDA
  reads one stray line from the top of the page when the page's own dialog closes (0.18.0 D14).
- Not covered: Narrator, JAWS, forced colours, plain-HTTP pages, a refused Approve on a listener
  request, and Days to keep in Listener statistics. No person listened. An automated agent read
  NVDA's speech.

## Setup

- Date: 2026-10-14, from about 17:50 to 19:15 local time (MDT).
- Operating system: Windows 11 Home, build 26200.9550.
- Screen reader: NVDA 2026.2 with eSpeak NG, its speech captured by the screen-reader-testing
  MCP server's NVDA add-on.
- Browsers:
  - Google Chrome 155.0.8059.79, started by hand with a new profile in a temporary folder and
    `--remote-debugging-port`. The profile was not signed in to any account.
  - Microsoft Edge 155.0.4283.45, InPrivate, with its own temporary profile and
    `--remote-debugging-port`. A first, non-private start signed that profile in to a
    Microsoft account by itself. That browser was closed and its profile deleted
    before any AutoDJ page was opened, and the InPrivate window was used instead.
  - Mozilla Firefox 157.0.1, the installed release build, in the agent's own Firefox profile.
- AutoDJ at b895fdef plus the D1 fix, Python 3.14.7, run with `autodj serve --stream` from a
  temporary folder with its own `config.toml`:
  - Music folder: 29 FLAC files, 13 from 10 Years (The Autumn Effect) and 16 from Above & Beyond
    (Group Therapy).
  - Pairing on, on 127.0.0.1 port 8093, over HTTPS with a self-signed certificate made for this
    run. Chrome and Edge ignored the certificate through their debugging connection. Firefox was
    taken past its warning page with the page's own Advanced and Proceed buttons.
  - Stations: AutoDJ (the default), Night Owl Radio with `[stations.nightowl.dmca] enabled = true`,
    and Sample Two, created during the run. The request page, the player page and the embed were
    on. For the framed player, a plain page on `http://127.0.0.1:8099` was listed in
    `embed_origins`.
  - Two `curl` listeners stayed connected to the AutoDJ and Night Owl streams, so the listener
    counts were not zero.
  - The server was stopped and started again several times, as the steps below say.
- No volume safety stage was used. Listen here and the player pages played the stream through
  the default output at the page volume (90 to 100 percent).

## Method

No person listened. An automated agent (Claude, run from Claude Code) drove the browsers and read
what NVDA spoke through the screen-reader-testing bridge. The quotes below are NVDA's speech text,
before eSpeak's symbol processing.

- Chrome and Edge: keys were sent to the page through the browser's debugging connection
  (Playwright over the Chrome DevTools Protocol), with the browser in the foreground so that NVDA
  followed focus. Those keys reach the page but not NVDA, so NVDA's own browse-mode keys were not
  used in these two browsers. The pairing code was typed through NVDA.
- Firefox: every key was pressed through NVDA (the bridge's key presses), including browse-mode
  keys such as e, k, t, d and NVDA's table keys. The pairing code was pasted from the clipboard.
- Page scripts were used for setup and to read state: moving focus to the first control of a
  step, opening collapsed cards, starting and stopping stations through the API, skipping songs,
  loosening the repeat rules so that requests could be accepted, framing the embed, and reading
  focus and the page's status regions.
- Session expiry was tested by replacing the browser's session cookie with an invalid value, so
  that the page's next request found no session.
- The bridge to NVDA drops after about 30 to 45 seconds without a call. One outage test lost its
  speech that way, so outage tests were run again later (the results below are from the second
  runs).
- No NVDA dialog was in front at any point, and none was dismissed.

## Limits

- No person listened. The capture is NVDA's speech text, not audio.
- In Chrome and Edge, keys went to the page directly, not through NVDA, so NVDA's own commands
  (browse-mode quick keys, table navigation) were used only in Firefox.
- Narrator, JAWS and forced colours were not sampled. All pages used HTTPS.
- Edge and Firefox were sampled for the subset of flows named below only.
- A refused Approve on a listener request could not be produced: approving a request for a song
  that had already been queued by hand was accepted, and the song was queued a second time.
- Days to keep in Listener statistics was not changed. Table navigation in the statistics tables
  was not driven; their captions and headers were checked in the page's markup.
- The music folder was a 29-track local copy, not a real library.

## Defects

Each with its severity. D1 is fixed in 0.21.0; the others are open.

- D1, blocker, fixed. The listener request page could not send a request in Chrome, with or
  without JavaScript: Send request answered with `{"detail":"Disallowed Origin"}`. The page sent
  `Referrer-Policy: no-referrer`, under which the browser sends `Origin: null` with the page's own
  form post, and the server refuses that Origin. The page now sends `same-origin`
  (`src/autodj/request_page.py`), with a test. Retested in Chrome, Edge and Firefox.
- D2, moderate. A status message that is the same as the one before it in the same region is not
  spoken again: Copy address or Copy now-playing link pressed twice, Save tags twice with the same
  result, and a folder checkbox toggled back (Edge). Each press should be said once.
- D3, moderate. Listen here turns off when the page's connection drops and stays off when it
  returns (two outages, 14 seconds and about two minutes). It should keep playing, with nothing
  said by the stream.
- D4, moderate. While AutoDJ is out of reach with Library tools open, "Could not load clockwheels:
  The AutoDJ server is not reachable." is spoken every 5 seconds. Shows, Categories and the intro
  rules say theirs once.
- D5, moderate. Delete category says "No clockwheel uses it." while a saved clockwheel step uses
  the category. After the delete, that step's summary still names the category until the step is
  edited, which then says the category no longer exists.
- D6, moderate. In the History and Hour preview tables, moving down a column other than the song's
  says only that cell ("18:31:23 PLAYED", "Fixed: ready to play STATUS"), not which song the row
  is. This changed when the song cells became plain cells.
- D7, moderate. After Save show, NVDA reads the whole Shows card (heading, help and list) before
  the Open list button.
- D8, minor. In a liner's Play dates, a mistyped date shows the server's own message: "Not before:
  Input should be a valid date or datetime, invalid date separator, expected `-`". It is linked to
  the field and focused, but it is not plain language.
- D9, minor. A file that is not audio uploads as a liner ("Uploaded broken.mp3") and fails only
  when it plays.
- D10, minor. A missing name in Categories and in Shows is said twice: once with the focused field
  and once more on its own.
- D11, minor. Check in Categories says the count twice ("Above set: 16 songs." and "16 songs."):
  the count line is not silent.
- D12, minor. After Remove condition 2, NVDA reads the focused condition's old legend ("Condition 3
  grouping") because the conditions are renumbered after focus moves.
- D13, minor. Switching stations also says the new station's song line and "Live", besides "Now
  controlling ...".
- D14, minor. After Move down, Remove or Add in a show's list, and when the queue list is drawn
  again, NVDA reads a cut-off fragment of the list ("d, On My Way to Heaven, 5:58 Move up Above &
  Beyond feat. Richard Be").
- D15, minor. A page reload says the last library job's result again ("analyse finished cleanly
  in 1:32.").
- D16, minor. In the Library tools folder table, toggling a checkbox switches NVDA to browse mode
  (Chrome and Edge).
- D17, minor. Send test on a webhook says "unavailable" while it sends, not "Sending".
- D18, minor. Save in the unsaved-tags dialog opens the other song without saying that the tags
  were saved.

Observations, not numbered:

- Approving a listener request for a song that was already queued by hand queued it a second
  time.
- In Firefox, after the request page's answer loads, NVDA began reading in the middle of its first
  line, skipping the heading. The first Alt+9 in Firefox said "Settings tab 9 of 9" without
  "selected"; later presses said it.
- In an earlier run of the outage test the "AutoDJ still cannot be reached" notice was not heard.
  The bridge to NVDA had dropped at the time; in the later run it was said once after about 20
  seconds.
