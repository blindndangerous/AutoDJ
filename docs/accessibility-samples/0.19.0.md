# Screen-reader sample for 0.19.0

This is the pre-release sample for AutoDJ 0.19.0, taken on the release commit b437a2c
("chore: release 0.19.0") on 2026-09-29. It covers the thirteen flows listed under "Release
sampling" in [Accessibility testing](../accessibility-testing.md) with NVDA and Chrome, and a subset
of them with NVDA and Firefox and with NVDA and Edge. The results apply only to the pairings, flows
and steps described below.

## What 0.19.0 ships with

- No new defect blocks a screen-reader user in the sampled flows. Every flow passed in every
  browser it was run in, apart from one settings step in Chrome (D1).
- New in 0.19.0 and confirmed by NVDA speech: the Paired devices card (rename puts focus back on
  Rename and says the new name once; Show pairing code says the code once, digit by digit; the
  countdown stays silent; a device that pairs meanwhile is announced once; Revoke confirms in the
  page's dialog). Pick mode offers only Similarity and Random walk. The Daypart, Mood arc and
  import-cues controls are gone. Play now on a page that never pressed Play starts the music at
  the page volume and says "Playing ... now." once. Keyboard shortcuts do nothing while a dialog is
  open. A liner delete asks in the page's own dialog and moves focus to the next liner.
- Five new minor or moderate defects, none of them a blocker: D1 (a number field saves a value
  above its own maximum without a word), D2 (Why this track does its BPM arithmetic wrong), D3
  (Shift+K says only "unknown"), D4 (a stream encoder traceback in the server log) and D5 (the
  first model download failed on Windows once). D4 and D5 are not screen-reader defects; they were
  found while setting up and are recorded so they are not lost.
- Carried over from 0.18.0 and still accepted: the pairing dialog's name and instructions are
  spoken twice when it opens (0.18.0 D4), and NVDA reads one stray line from the top of the page
  when the page's confirmation dialog closes (0.18.0 D14). This run heard the D14 line in Firefox
  and Edge as well as Chrome, and after the rename dialog closes, not only after a delete.
- Not covered: Narrator, forced colours, NVDA+key commands, plain-HTTP pages and the worklet
  effects themselves. No person listened; an automated agent read NVDA's own speech log.

## Setup

- Date: 2026-09-29, 08:22 to 10:10 local time (MDT), after about 90 minutes of setup.
- Operating system: Windows 11 Home 25H2, build 26200.9457.
- Screen reader: NVDA 2026.2 (2026.2.0.57664), laptop keyboard layout, eSpeak NG. NVDA's log
  level was already "input/output", which is what the capture below relies on.
- Browsers, each with a new temporary profile started by Playwright (`playwright cli`, version
  1.63.0, from the repository's `node_modules`) and deleted when the browser closed. None was
  signed in to any account.
  - Google Chrome 154.0.8037.58 (`--browser=chrome`).
  - Mozilla Firefox 156.0.1, the installed release build driven over WebDriver BiDi
    (`--browser=moz-firefox`), not Playwright's patched Firefox.
  - Microsoft Edge 154.0.4258.37 (`--browser=msedge`). Playwright starts it with forced sign-in
    switched off; the window title showed "Profile 1".
- AutoDJ 0.19.0 at b437a2c, Python 3.14.7, served straight from `src/autodj/static` (there is no
  build step any more). It ran from a temporary folder with its own `config.toml`:
  - Music folder: a local folder holding 46 FLAC files copied (not moved) from `Z:/Beetsmusic`:
    13 from 10 Years (The Autumn Effect, timed lyrics), 8 from Aesthetic Perfection ('Til Death,
    timed lyrics), 11 from Bury Tomorrow (Runes), 7 from In This Moment (Blood) and 7 from Above &
    Beyond (Group Therapy). 42 were indexed with `autodj index` before the run; the other 4 were
    added later so the page's Index job had real work to do.
  - Why not the NAS share: `autodj index --limit 60` with `music_dir = "Z:/Beetsmusic"` reads the
    tags of every file in the library before it applies the limit. After 30 minutes it had still
    not finished listing the 76,728-track share, so it was stopped and the local copy used.
  - `[server] lan = true` (pairing on) on port 8093, with `ssl_certfile` and `ssl_keyfile`
    pointing at a self-signed certificate made for this run (`localhost`, `127.0.0.1` and the
    machine name). Each browser was taken past its certificate warning once with the warning
    page's own Advanced and Proceed buttons, and used `https://localhost:8093`.
  - `web_state.json` was seeded with a volume of 0.001413, the gain of the 5 percent slider
    position, so the server started at 5 percent.
  - `autodj serve` for most of the run; `autodj serve --stream` for the stream flow and the
    History empty state. The server was stopped with `taskkill /T /F` and started again several
    times, as the steps below say.
  - The MuQ model was downloaded into the run folder's `models` and deleted with it.
- Volume and safety stage, in every page of all three browsers: a Playwright context init script,
  which runs before the page's own scripts on every load, reload and the reload after pairing,
  replaced `AudioContext` with a subclass whose `destination` is a gain of 1 (a tap, read by an
  AnalyserNode) feeding a gain fixed at 0 in front of the speakers. Any media element that played
  outside the page's audio graph (only the stream player did) was first routed into the same kind
  of zero-gain graph. Before and during every step that could make sound, the zero gain was read
  as 0 through DevTools and `AudioContext.name` as the subclass. The page volume was 5 percent
  throughout (once 6 percent for one arrow press). The page's own audio graph therefore never
  reached the speakers.

## Method

No person listened. An automated agent (Claude, run from Claude Code) drove the browsers and read
what NVDA sent to speech from NVDA's own log (`%TEMP%\nvda.log`, "Speaking" lines at input/output
level). The quotes below are that text, before NVDA's symbol processing, so they show "+0.1 dB"
where eSpeak says "plus 0.1 d B".

- The screen-reader-testing MCP bridge was connected in silent mode at the start. Its log missed
  the page's speech (it recorded browser toolbar speech only), and silent mode also silences NVDA
  for anyone else using it, so it was disconnected at 08:30 and not used again. NVDA spoke
  normally for the rest of the run.
- Keys: every key in the steps below was a real Windows key press sent through the windows-mcp
  server, so NVDA handled it, with the browser in the foreground. The NVDA modifier could not be
  sent that way (CapsLock+Space arrived as a plain Space), so NVDA+Space and NVDA+F2 were not
  used. Single-letter shortcuts were sent with focus on a slider, where NVDA is in focus mode.
- To check that shortcuts do nothing while a dialog is open, the letters had to reach the page
  while NVDA was in browse mode on a dialog button, which real keys cannot do without NVDA+Space.
  Those letters (n, k, m, Shift+T, Shift+E, Shift+Q) were sent through DevTools instead, and the
  page's own key log showed they arrived.
- Page scripts were used only for setup and to read state: moving focus to the starting control
  of a step, opening collapsed cards, filling the pairing code, device names, search text and
  profile name, choosing the liner file to upload, pairing extra devices through `/api/pair`,
  filling the History with 50 skips through `/api/skip` while the page was silent, and reading the
  server's status, the decks, the stream player and the safety stage.
- Owner activity: someone used the machine from 08:23:34 to about 08:29:09 through NVDA Remote.
  NVDA was restarted at 08:23:43, very likely because the silent bridge session had muted it. The
  agent sent nothing in that time and resumed at 08:30:09, after 60 seconds without input; the
  pause lasted about six and a half minutes, longer than the five-minute limit. No other input
  that the agent did not send was seen; every later idle time matched the agent's own keys.
- No NVDA dialog was in front at any point, and none was dismissed.

## Limits

- No person listened. The capture is NVDA's log, not audio.
- NVDA+key commands could not be sent, so the shortcuts were not tried in browse mode, and the
  dialog-blocking check used DevTools keys.
- Narrator and forced colours were not sampled.
- All pages used HTTPS. The plain-HTTP note under Transition effect was only seen to stay hidden
  on the HTTPS page, and no transition effect was switched on, so the worklet effects themselves
  were not heard or measured.
- Firefox and Edge were sampled for the subset of flows named below only; stream mode was
  sampled in Chrome only.
- The music folder was a 46-track local copy, not the owner's library.
- Crossfade seconds set to 0 was checked in the Fixed transition mode only.
- Session expiry was tested by signing out. "Make new link" was not pressed. The media Play key
  was sent by calling the page's own Media Session handler, not with a real key.
- Discovery staying off after a restart, the Serato cue import and the Sonos title were not
  sampled.
- Copy address put this run's stream address on the machine's clipboard; that address stopped
  working when the run folder was deleted.

## Defects

Each with its severity and the code it comes from. None is fixed in 0.19.0.

- D1, minor. Crossfade seconds accepts a value above its own maximum without a word. The field is
  `min="0" max="20"` and NVDA reads it as a spin button, but 99 followed by Tab was saved as 99 and
  nothing was said; other number fields refuse out-of-range values and say why ("Could not save
  ...: enter ... It is still ..."). Fade-in seconds uses the same rule. Cause: the page sends any
  value of 0 or more (`atLeastZero`, `src/autodj/static/modules/settings-panel.js` lines 97 to 100
  and 130 to 131) and the server accepts any non-negative number
  (`src/autodj/settings_bodies.py` line 126).
- D2, minor. Why this track rounds the two BPM values and their difference separately, so it can
  say "BPM lifts 129 to 133, up 3." (`src/autodj/explain.py` line 58).
- D3, minor. Shift+K on a track with no detected key says only "unknown" (Firefox and Edge). The
  page's fallback "Key unknown" in `src/autodj/static/modules/hotkeys.js` line 259 is never used,
  because the server already sends the word "unknown" as `key_spoken`
  (`src/autodj/dj_meta.py` lines 407 to 408).
- D4, minor, not a screen-reader defect. In stream mode the server log got two
  "ValueError: I/O operation on closed file" tracebacks from the stream reader thread
  (`src/autodj/stream.py` line 342, calling `read` at line 100), around the two Quality changes.
  The stream played normally afterwards.
- D5, moderate, not a screen-reader defect, seen once. The first `autodj index` into an empty
  `models` folder failed with "Failed to download model 'OpenMuQ/MuQ-large-msd-iter': [WinError
  1314] A required privilege is not held by the client" while Hugging Face linked `config.json` in
  its cache (Windows without Developer Mode; `huggingface_hub` 1.31.0 had just warned that it would
  not use symlinks there). Running the same command again worked. The download is
  `snapshot_download(..., cache_dir=index_cfg.model_dir)` in `src/autodj/model.py` line 101.

Observations, not numbered:

- `autodj index --limit N` still reads the tags of every file in the music folder before applying
  the limit (`src/autodj/indexer.py` lines 1406 to 1420 and 1538 to 1539), so it is no quick test on
  a large NAS library, although its help suggests `--limit 20` for that.
- The rename dialog, like the pairing dialog, is spoken twice when it opens, and Chrome and Edge
  give it the description "Device name 1 to 64 characters", taken from its content.
- The 0.18.0 D14 line (a stray line from the top of the page as the page's dialog closes) was heard
  in Firefox and Edge too, and after the rename dialog closes, not only after a confirmed delete.
- In all three browsers, Escape on the open Harmonic mixing list kept the option that was
  highlighted. This is the browsers' own drop-down behaviour.
- The server log holds about 114 `ConnectionResetError: [WinError 10054]` tracebacks from asyncio
  on Windows, one per closed browser connection. They are noise, but they hide real errors such as
  D4.
