# Screen-reader sample for 0.22.0

This is the pre-release sample for AutoDJ 0.22.0, taken on 2026-10-23 on master at f8660479, the
commit the release branch starts from. It covers the flows listed under "Release sampling" in
[Accessibility testing](../accessibility-testing.md) with NVDA and Firefox, and the new 0.22.0
pages: Settings, Breaks; Settings, Time checks; Stereo Tool in Settings, Sound; turning listener
requests on and off; and the Save changes and Discard changes buttons in Settings. The results
apply only to this pairing and to the flows and steps described below.

## What 0.22.0 ships with

- No release blocker was found. Every flow that was driven could be completed with the keyboard
  and NVDA.
- One flow fails: Settings changes and their feedback (D1). Save changes and Discard changes in
  Settings, new in 0.22.0, turn themselves off when pressed, so focus falls to the page and NVDA
  says the page title. The result, such as "Settings saved for AutoDJ.", is never spoken. This
  happened on every Settings tab tried, and it also silences the results that Show the next song
  publicly and Opus quality used to say.
- New in 0.22.0 and confirmed by NVDA speech: Take listener requests and Approval in the Listener
  requests card, with "Requests are closed" on the request page; Settings, Breaks; Settings, Time
  checks; Download Stereo Tool, Save licence key and Clear licence in Settings, Sound; the Unsaved
  settings dialog; and Listen here playing on after the page's connection returns.
- Fourteen other defects, none of them a blocker. D2 is moderate and the rest are minor. D2: the
  Clockwheels Add a step dialog reads the whole step form aloud, twice, when it opens.
- Fixed since 0.21.0 and not heard again in this run: 0.21.0 D2 (a repeated message not spoken
  again; checked with Copy address, Copy now-playing link and a folder checkbox), D3 (Listen here
  stopping after an outage), D6 (table rows not naming the song), D7 (Save show reading the whole
  card), D9 (a file that is not audio uploading as a liner), D12 (a removed condition's old
  legend), D13 (extra speech on a station switch) and D15 (a reload repeating the last job's
  result).
- Carried over and still accepted: a dialog's name is spoken twice when it opens (0.18.0 D4),
  heard with the pairing dialog, Rename device and Add category or Edit category. A missing or
  refused value is said twice, once with the focused field and once on its own (0.21.0 D10),
  heard in Settings, Breaks and in a clockwheel condition.
- Not covered: Chrome, Edge, Narrator, JAWS, forced colours, pages without JavaScript in a
  browser, webhook Send test, a long library job, timed lyrics and the other steps listed under
  Limits. No person listened. An automated agent read NVDA's speech.

## Setup

- Date: 2026-10-23, from about 14:25 to 15:40 local time (MDT).
- Operating system: Windows 11 Home, build 26200.9711.
- Screen reader: NVDA 2026.2 with eSpeak NG, its speech captured by the screen-reader-testing MCP
  server's NVDA add-on in silent mode, with the validator persona. NVDA on this computer reports
  "clickable", indentation and formatting; those words in the quotes come from NVDA's settings,
  not from AutoDJ.
- Browser: Mozilla Firefox 158.0.1, the installed release build, in the agent's own Firefox
  profile. It was taken past its certificate warning with the warning page's own Advanced and
  Proceed buttons.
- AutoDJ at f8660479, Python 3.14.7, in a no-model install (no MuQ, PyTorch or model weights),
  run with `autodj serve --stream` from a temporary folder with its own `config.toml`:
  - Music folder: 27 songs copied for this run, 14 FLAC files from Amethystium (Odonata) and 13
    MP3 files from Apocalyptica (Shadowmaker). They were imported with `autodj index` in no-model
    mode, so they had basic analysis (cue points, beats and song structure) and no advanced
    analysis.
  - Pairing on (an access token in `config.toml`), on 127.0.0.1 port 18443, over HTTPS with a
    self-signed certificate made for this run.
  - Stations: AutoDJ (the default), Night Owl Radio with DMCA mode on, and Sample Two, created
    during the run. The request page, the player page and the embed were on for AutoDJ and
    Night Owl Radio. For the framed player, a plain page on `http://127.0.0.1:18099` was listed in
    the allowed embed sites.
  - Two `curl` listeners were connected to the AutoDJ and Night Owl Radio streams for most of the
    run, so the listener counts were not zero.
  - The server was stopped and started once for the outage test.
- No volume safety stage was used. Listen here and the player pages played the stream through the
  default output.

## Method

No person listened. An automated agent (Claude, run from Claude Code) drove Firefox and read what
NVDA spoke through the screen-reader-testing bridge. The quotes below are NVDA's speech text,
before eSpeak's symbol processing.

- Every key was pressed through NVDA, including NVDA's browse-mode keys (e, k, b, t), its table
  keys, and NVDA+Space to switch between browse mode and focus mode. The playback shortcuts were
  pressed in focus mode, as the page's Keyboard shortcuts dialog tells NVDA users to do. Text was
  typed through NVDA. Before each typed text or Enter, the agent checked the window title with
  NVDA+T.
- Page scripts were used for setup and to read state: moving focus to the first control of a
  step, opening a tab or a collapsed card, starting, stopping and skipping stations through the
  API, loosening the repeat rules so that a request could be accepted, discarding drafts left
  over from a step, and reading focus, the page's status regions and the audio elements.
- Session expiry: the browser's session cookie is HttpOnly, and the Firefox tools used here
  cannot replace it. The session was ended on the server instead, with `autodj devices revoke`
  for this browser, and a new code came from `autodj devices pairing-code`.
- Outage: the server process was stopped for about 45 seconds and started again.
- A second paired device was made by sending the code shown on the page to `/api/pair` with
  `curl`, under the name Sample phone.
- Voice liner files were chosen in Windows' own File Upload dialog, opened from the page's Choose
  liner file button, with the path typed through NVDA. Two earlier attempts to set the file with
  the Firefox tools' upload command typed the path as key presses into the page instead, which
  fired several playback shortcuts (mute, skip, shuffle and Track info). Those attempts are not
  part of any result below.
- The pages without JavaScript were checked only in their markup, fetched with `curl`; Firefox's
  JavaScript was on for every NVDA step.
- No NVDA dialog was in front at any point, and none was dismissed. Earlier evidence from the
  same day, with the same NVDA, Firefox and method, is cited under "Earlier evidence".

## Limits

- No person listened. The capture is NVDA's speech text, not audio.
- One pairing only: NVDA with Firefox. Chrome, Edge, Narrator, JAWS and forced colours were not
  sampled. All pages used HTTPS.
- The server ran in stream mode the whole time, so Settings skipping Stream outside stream mode
  was not checked.
- The library had 27 songs and no advanced analysis. Search fit on one page, so Previous and Next
  were not driven. No song had lyrics, so timed lyrics were not heard. Library jobs finished in
  seconds ("index finished cleanly in 0:04."), so a job running for several minutes was not
  heard, and the output log was not reviewed.
- Not driven: webhook Send test (no webhook was set up), Days to keep in Listener statistics, a
  refused Approve on a listener request, a liner Play dates change and a failing Test now, a
  voice pack zip upload, Download Stereo Tool with the terms accepted (it fetches about 320 MB
  from Thimeo), a failed folder save with the server stopped, a new History row while the table
  is read, the Hour preview's 30-second refresh, Shift+H from another tab, and Track info
  returning focus to its search result.
- The request page and the public status page were not used in a browser without JavaScript;
  their server-made HTML was checked for titles, headings, the definition list and the
  invalid-field mark.

Each with its severity. All are open; none is a blocker.

- D1, moderate. Save changes and Discard changes in Settings turn themselves off when pressed, so

  liners, and with Discard changes. Save changes in the Unsaved settings dialog also says nothing
  about the save. Focus should stay on a control and the result should be said once.
- D2, moderate. Opening Add a step in Clockwheels reads the dialog's whole text twice: the
