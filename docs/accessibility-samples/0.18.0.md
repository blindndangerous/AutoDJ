# Screen-reader sample for 0.18.0

This is the pre-release sample for AutoDJ 0.18.0. The full run was taken on commit 2e42078;
the later checks below cover the fixes up to the release commit. It covers the twelve flows listed under "Release sampling" in
[Accessibility testing](../accessibility-testing.md) at the time with NVDA and Chrome, and a subset of them with
NVDA and Firefox and with NVDA and Edge. The results apply only to the pairings, flows and steps
described below. It replaces an earlier draft sample of 0.18.0 (commit f10050e); none of that
draft's results are reused here.

This record is a summary. The step-by-step speech transcripts of every run are in the git
history of this file.

## What 0.18.0 ships with

This summary reflects the last check on 2026-09-28 (master cfb3ac7, see "Auto-play and D14
check" below), on top of the final verification (master c9f54ff). It covers only the
pairings and steps recorded here.

- Fixed and verified: D1, D2, D3, D5 to D13, D15, D16, D17 and D18. D16 and the D18 Listen here
  and mute steps were checked by NVDA speech in the final run. D15, D17 and D18 were also checked
  by reading the page's audio state, because they concern volume and playback.
- Accepted as designed: D4. The pairing dialog's name and instructions are spoken twice when it
  opens, as they are for any named dialog in these browsers.
- Accepted as a known NVDA and Chrome quirk (owner decision, 2026-09-28): D14 (minor, improved
  twice). After Delete profile, Revoke or Clear queue is
  confirmed in the page's own dialog, NVDA no longer reads the page title, "unknown" or the button
  that opened the dialog. It still reads one stray line from the top of the page (for example
  "banner landmark heading level 1 AutoDJ" or "same page link Skip to main content") before the
  new focus target. The same line is read when the dialog is closed with Cancel or Escape, so it
  comes with closing the dialog, not with the delete.
- Media Play key on a page where Play was not pressed: fixed in 25a81dc and checked in Chrome and
  Firefox by page state (pass). This is the likely cause of the unexplained Firefox playback in the
  final verification. A real operating-system media key was not sent.
- Not covered: Narrator, forced colours, and NVDA+key commands. No person listened; an automated
  agent captured NVDA's speech.

## Setup

- Date of the full run: 2026-09-27 22:51 to 2026-09-28 00:04 local time (MDT). The four later
  runs were on 2026-09-28 between 04:35 and 09:41.
- Operating system: Windows 11 Home 25H2, build 26200.9457.
- Screen reader: NVDA 2026.2 (AMD64), laptop keyboard layout. The synthesizer changed during the
  full run (ETI-Eloquence, then "No speech", then eSpeak NG, switched by someone at the machine);
  the capture records what NVDA sent to speech, so the voice does not change the results.
- Browsers: Google Chrome 153.0.8010.53 and Mozilla Firefox 156.0.1, each in the automation
  profile of its DevTools MCP server; Microsoft Edge 154.0.4258.37 with a new, empty profile in a
  temporary folder, deleted afterwards.
- Narrator: not sampled. The screen-reader-testing MCP server offers only NVDA.
- AutoDJ: version 0.18.0, build 2e42078, with the web bundle built from that commit (0.18.0 still
  had an `npm run build` step). The server ran from a temporary folder with its own
  `config.toml`: music folder `Z:/Beetsmusic` (the NAS share, read only), a local copy of the
  owner's 76,728-track index, port 8093. It ran as `autodj serve --lan` (pairing on, browser
  audio) for most flows, and as `autodj serve --lan --stream` for the stream flow and the Sonos
  check. The browsers used `http://localhost:8093`.
- Volume: the page volume was 5 percent or lower before anything played, and playback was paused
  whenever a step did not need it. The later runs also put a zero gain between the page's audio
  graph and the speakers, so nothing was audible, and read the engine's gains through it. The
  stream was read by a script, not played aloud.

## Method

No person listened. An automated agent (Claude, run from Claude Code) drove the browsers and
recorded what NVDA spoke through the screen-reader-testing MCP server: in "live" mode in the full
run and in "silent" mode (NVDA logs what it would say, the synthesizer stays quiet) in the later
runs. Where a result says NVDA spoke something twice, NVDA's own log showed two separate speak
calls.

- Keys: in the full run, Chrome and Firefox keys mostly went to the page through DevTools, which
  bypasses NVDA's key handling; steps marked "real keys" were Windows key presses (SendInput
  through the windows-mcp server), which NVDA handled. Every Edge key, and every key in the later
  runs, was a real Windows key press.
- The Insert key did not reach NVDA as a modifier, so NVDA+F2 pass-through and other NVDA+key
  commands could not be exercised.
- Page scripts were used for setup and to read state, never to decide what NVDA said: setting
  the volume before playback, moving focus to the starting control of a step, opening collapsed
  sections, pairing, and filling the History through `/api/skip` with the page silent.
- Someone used the machine a few times during the runs; the affected steps were repeated, and no
  result depends on input the agent did not send.

## Limits

- No person listened, and most Chrome and Firefox steps of the full run bypassed NVDA's own key
  handling.
- NVDA+key commands could not be sent, so browse-mode use of the hotkeys was not sampled.
- Narrator and forced colours were not sampled.
- Firefox and Edge were sampled for the subset of flows named below only.
- No library job could be left running for several minutes; the longest was Prune, 58 seconds.
- Session expiry was tested by signing out, not by a session timing out. "Make new link" was not
  pressed.
- The volume slider was only sampled between 0 and 20 percent.
- The second verification captured no NVDA speech (an NVDA dialog held the foreground); its
  results rest on live-region text and engine state.
- The Edge revoke step of D14 was never run; the revoke was checked in Chrome.
- Media Session actions were sent by calling the page's own handler, not with a real media key.

## Flows sampled

Results of the full run (build 2e42078), with the defects found. "Not sampled" means the flow was
not run in that browser. The flow "Settings, Browser access" was added to the release-sampling
list after 0.18.0 and is not part of this sample.

- Flow 1, authentication, session expiry and connection status: Chrome pass (D4), Firefox pass
  (D4), Edge pass (D4).
- Flow 2, section tabs and disclosures: Chrome fail for the tab list (D3; disclosures and the
  shortcuts dialog pass), Firefox fail (D3), Edge fail (D3).
- Flow 3, playback controls, seeking, volume and spoken hotkeys: Chrome pass for the spoken
  hotkeys, Play and Pause, Skip focus and seeking, fail for the volume controls (D1) and for m
  with real keys (D5); Firefox fail for Play and Pause (D8), the rest pass apart from D1; Edge
  pass apart from D1 and D5.
- Flow 4, search, queue additions, reordering, removal and empty states: Chrome pass, Firefox
  pass, Edge pass.
- Flow 5, now-playing changes, metadata, cue descriptions and timed lyrics: Chrome pass; not
  sampled in Firefox or Edge.
- Flow 6, settings changes and their status or error feedback: Chrome pass (D14); Firefox fail
  for the open Harmonic mixing list (D7), the rest pass; Edge pass.
- Flow 7, library-job status and the output log: Chrome pass for start and end each spoken once
  and for Stop (D6, D12, D13); Firefox pass (D12, Stats and the log only); Edge pass (D12, Stats
  and the log only).
- Flow 8, stream mode: Chrome pass (D11); not sampled in Firefox or Edge.
- Flow 9, voice liners: Chrome pass (D10); not sampled in Firefox or Edge.
- Flow 10, EQ: Chrome pass; not sampled in Firefox or Edge.
- Flow 11, History: Chrome pass; not sampled in Firefox or Edge.
- Flow 12, Why this track: Chrome pass (D9); not sampled in Firefox or Edge.
- Sonos now-playing (ICY metadata, read by a script from the stream): pass. The title was
  "Artist - Title" of the current track and changed at the Skip.

## Defects

Each defect with its severity, what was found, and its final status.

- D1, moderate. Volume settings below about 23 percent were reported as 0 and could not be
  adjusted by arrow keys, because the server rounded the gain to two decimals and the page wrote
  it back into the slider. Fixed in 0983057; verified (pass).
- D2, moderate (found in the code). After a page load, browser playback ran at full gain until
  the volume slider was moved. Fixed in 0983057; verified on load and on the next track (pass).
- D3, minor. Moving between section tabs spoke each tab twice, in all three browsers. Fixed in
  0136510; verified in Chrome, Firefox and Edge (pass).
- D4, minor. The pairing dialog's name and instructions are spoken twice when it opens, in all
  three browsers. Accepted: the dialog stays named, as WCAG expects, and NVDA reads any named
  dialog this way.
- D5, moderate. With keys passing through NVDA, m worked once and then did nothing, because the
  page's keyup arrived as "Unidentified" and the pressed-key latch never cleared. Fixed in
  83097aa; verified in Chrome and Edge (pass).
- D6, moderate. A failed library job reported the runner's own last line instead of the reason.
  Fixed in 4c0ddb2; verified (pass).
- D7, minor. In Firefox's open drop-down list the Harmonic mixing options lost their spoken
  words. Fixed in eef671a; verified in Firefox (pass).
- D8, minor. In Firefox, Play or Pause spoke the status and the new button label. Fixed in
  76bf4d1; verified in Chrome and Firefox (pass).
- D9, minor. Why this track dropped the arrow between two values at NVDA's default punctuation
  level. Fixed in eef671a; verified (pass).
- D10, minor. Test now did nothing and said nothing while browser playback was stopped. Fixed in
  493e2cd; verified (pass).
- D11, minor. The stream address's "only works on this computer" note was not part of the
  field's description. Fixed in d580ed1; verified (pass).
- D12, minor. When the output log got focus, NVDA read the whole log in one utterance. Fixed in
  929f60d; verified in Chrome (pass).
- D13, minor. Shift+J during a Prune read the raw progress bar. Fixed in 4c0ddb2; verified
  (pass).
- D14, minor. After a delete or revoke confirmed in the page's own dialog, NVDA read the page
  title, "unknown" and the banner before the new focus target. Improved by 0f345f1, fb3476d and
  cfb3ac7: the title, "unknown" and the opener are no longer read, but one line from the top of
  the page still is, also when the dialog is closed with Cancel or Escape. Open; ships in 0.18.0
  as a known NVDA and Chrome quirk.
- D15, serious (found in the first verification). A server restart reset the volume to 100
  percent and a page that had been playing resumed at it. Fixed in e67bd02; verified in browser
  playback and stream mode (pass).
- D16, minor (first verification). In browse mode the Play or Pause button's text read as one
  word in Chrome and over three lines in Firefox. Fixed in d993705; verified with NVDA in the
  final verification in Chrome and Firefox (pass).
- D17, minor (first verification). In Firefox the first Play after pairing said "Playing" while
  nothing played. Fixed in ac585a8; verified in Firefox and Edge by engine state and live-region
  text (pass).
- D18, moderate (second verification). In stream mode the Listen here player ignored the volume
  the slider showed until the slider was moved. Fixed in b653185; verified in Chrome in the final
  verification (pass).

## Verification runs

- First verification (master e2c6cd9, 2026-09-28 04:35 to 05:30, Chrome, Firefox and Edge, real
  keys, NVDA speech in silent mode). It checked the fixes for D1 to D14: D1, D2, D3, D5 to D13
  passed, D4 was accepted as designed, and D14 still failed for deletes confirmed in the page's
  dialog. It found D15, D16 and D17. It also read the gains of all 35 browser transition effects
  during Skip at 5 percent: the music decks never went above the page volume, and reverse_reverb's
  swell (3.6 times) was the one effect well above the music. The effect levels were changed
  afterwards and checked in the second verification.
- Second verification (master 605c457, 06:31 to 07:04). An NVDA dialog held the foreground, so no
  NVDA speech was captured and results rest on live-region text and engine state. D15 and D17
  passed, the liner test played through the master at 5 percent and stayed silent when muted, and
  no transition effect raised the output above a full-scale track at that volume. D14 and D16
  were not verified with NVDA. It found D18.
- Final verification (master c9f54ff, 08:40 to 09:04, Chrome and Firefox, real keys, NVDA speech).
  D16 and D18 passed; D14 improved (no page title or "unknown") but still failed; a short
  regression listen in Chrome (tab list, Play and Pause, m, Shift+L) passed. A Firefox page where
  Play was never pressed started playing at 5 percent for about 45 seconds; it was not reproduced,
  and the likely cause, a Media Session play action, was fixed in 25a81dc.
- Auto-play and D14 check (master cfb3ac7, 09:27 to 09:41, Chrome and Firefox). Media Session play
  and pause on a page where Play was never pressed left it silent and the server unchanged, while
  a page that had pressed Play still answered them (pass). D14 improved again (the opener is no
  longer read) but one line from the top of the page is still spoken as the dialog closes, which
  led to the owner's decision to ship it as a known quirk.
