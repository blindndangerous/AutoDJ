We'll build the playout changes into AutoDJ, using its server for the continuous mix and its browser interface for control and listening. The sound reference is the B version of the [latest listening examples](playout-round9/index.html). The [saved track points](playout-cues.md) and [earlier research](playout-research.md) remain available. Linux is the target; WSL is useful for development.

Once this is built, the everyday workflow will be:

1. Open Library tools and choose Add folder under Music folders. Select a folder on the machine running AutoDJ. The first version handles folders; adding individual music files can follow.
2. Choose Add subfolders and Perform advanced analysis. Both boxes start checked for new music folders. Save these choices with the folder so later rescans behave the same way.
3. AutoDJ reads each new file, finds its Start and End, suggests a Segue and prepares its level. Each song becomes available as soon as its basic preparation finishes. There is no compulsory review page.
4. If Perform advanced analysis is checked, queue the longer matching and beat-analysis work in the background. The song can already play in Random walk or from the queue. Similarity selection can use it once the necessary matching data is ready.
5. Add more folders or use Rescan to find new files in existing ones. Playback and new-file preparation take priority over background analysis. Show analysis progress and failures without removing a playable song from the library.
6. AutoDJ fills Intro and Outro when it can find them. Adjust them later in the optional song-points editor. An unknown Intro means there is no safe intro time for a liner; an unknown Outro means there is no early talk-over window at the ending.

The existing library jobs already run in the background, but current Index still makes songs wait for matching analysis before they enter the library. Separating those two stages is part of the implementation. Basic preparation still has to read the audio, so we will measure import time during the folder test.

Music folders and Voice liner folders will be separate lists. Liners currently come from one folder, normally `<index_dir>/<name>/liners`, or the configured `playback.liners_folder`. AutoDJ scans that folder's top level and stores uploads there. Liners are separate from the music collection.

Give Voice liners the same Add folder, Rescan and Remove actions, including Add subfolders. New liner folders can include subfolders by default. Liners need basic timing and level preparation, but not the advanced music-matching job. Keep the existing upload action and its current destination. Two liner files with the same name in different folders must remain distinct, with their folder shown when needed. Registered liner files must stay out of music selection, including when their folder sits inside a music folder.

Folder changes should preserve the work already done. Registering a parent folder and one of its subfolders must not add the same file twice. A confirmed move of an unchanged file must retain its points, history, prepared audio and completed analysis. Reuse the existing file-move checks, extending them across the registered folders. Artist and title alone do not establish that two files are the same edit. Removing a folder stops using that source without deleting files or saved information; files still covered by another registered folder remain available.

We can manage this through the web without abandoning `config.toml`. It remains the place for installation defaults. Import the current music and liner locations into the folder lists once, preserving their existing scan scope. After that, the web-managed lists and their checkboxes are saved with the active library and survive restarts. An intentionally empty list stays empty. Changes to a playback profile should not change the source folders.

AutoDJ already saves browser playback settings in `web_state.json`. Reuse its validated save-and-restore approach for the new controls, while giving folder management its own library actions. Folder paths currently belong to configuration, so this ownership change needs explicit implementation. Routine folder and playback changes should no longer require editing TOML or restarting the server. Keep Beets available as an alternative music source.

The settings and actions fit into the current interface as follows:

- Library tools gains Add folder, Rescan and Remove for music and liners. The current Index and Analyse jobs remain available as advanced tools and supply the background analysis work. Perform advanced analysis belongs to each music folder and starts checked. Unchecking it stops scheduling further analysis for that folder; completed results remain usable.
- Pick mode keeps Similarity and Random walk. Extend Random walk to the whole playable library, including songs still waiting for detailed analysis. Similarity still requires matching data for its seed and candidates.
- Tracks before a song can repeat and Tracks before an artist can repeat keep their existing controls. Random walk already checks recent songs; extend it to respect the artist limit too. Its BPM range still needs a known BPM when enabled.
- Transition mode keeps Full intro and outro, Outro fade, Fixed (skip silence) and Fixed. Add Use saved segue points to the same list.
- Crossfade seconds remains the fade-length control. Start at 1.5 seconds with the accepted exponential curve. The new item enters one-third of the way through that fade: 0.5 seconds after it begins, with up to 1 second of the old item underneath. The saved Segue marks entry, so fading starts before it. A shorter remaining file tail limits the overlap. Changing this one length scales the handoff.
- Fade-in seconds remains available for the existing modes. Hide it for Use saved segue points, where the incoming item starts at its prepared level.
- Transition effect stays at none and EQ-ducked crossfade stays off for this setup. EQ ducking cuts bass during a mix; it is separate from the liner's volume ducking.
- Existing Beatmatch, Drop mixing, Key shift, Phrase align, Outro / intro align, Filter sweep and Keep vocals apart controls must not override the saved points and agreed fade in the first implementation. Hide controls that do not apply and retain their values for other modes. Clarify that the existing Preset control steers music selection by BPM.
- Voice liners keeps its enable switch, Every N tracks, Every N minutes, random-window triggers and Random/Sequential rotation. These choose when a liner is due and which recording to use.
- Talk up to the vocal keeps its existing switch and scheduler. Enable it for this setup and extend it to use saved Intro and Outro points. If a complete liner will not fit, delay the incoming song instead of placing speech over its first vocal.
- Overlap start is the new per-liner timing field. It defaults to 0 seconds. Plague uses 5.3 seconds. Start and End still determine which part of the recording plays.
- Duck depth already exists. Set it to 0 dB for this setup, leaving the existing control available for other uses.
- Replace the ReplayGain normalisation checkbox with Loudness processing: Off, ReplayGain or Smooth (Type B). ReplayGain keeps its current tag-based behavior and target-loudness field. Smooth uses measured source preparation and continuous compression, with no additional ReplayGain gain. Existing enabled and disabled ReplayGain settings map to ReplayGain and Off respectively. Save the new choice in profiles too.
- Add an edit action to the existing cue display. It opens Song points, with time boxes, Play from here, Set to current position and Save. The page must work with a keyboard and screen reader. Saving a point does not repeat detailed analysis.

The song points keep their separate purposes. Start skips unwanted leading silence. Intro marks the first words. Outro marks where a liner can begin over the ending. Segue marks where the next item enters, and End stops playback while retaining any wanted tail.

Basic preparation supplies Start and End and suggests a Segue when it finds a convincing ending. Otherwise leave Segue unset and use Outro, then End, as the fallback. A saved Segue takes priority over Outro. Entering a later Outro must not push the song change later. Rescanning an unchanged file or completing advanced analysis must preserve points entered or imported by the user.

Reuse the timing AutoDJ already has to fill Intro and Outro points. The first timed lyric can identify where the words begin. The last lyric can help locate an Outro, although the code estimates when that line finishes. Existing loudness-based detection can also supply rough points; a change in loudness does not necessarily mean the singing has stopped. Automatically found points take effect immediately and are marked as detected in the editor. Use existing data during import and fill missing points as background analysis finishes. This does not add another required scan or review step. Keep manual and imported points when new analysis arrives. We can refine detection later.

The talk-up feature in the [current changelog](CHANGELOG.md) already schedules liners in server audio and stream mode. It takes the first timed lyric, falling back to the detected intro end, and aims to finish 0.25 seconds before it. A short liner can start partway through the incoming intro. If it needs more room, the scheduler tries the existing crossfade; if it still cannot fit, or the vocal point is unknown, it starts the liner anyway. It does not delay the next song or use an earlier, separately marked Outro window. Browser-deck playback does not have this timing. We will extend this scheduler and its tests for the rules below.

Under the planned rules, all voice tracks, IDs and jingles use the same timing. With Overlap start at 0, fit the complete liner as late as possible within the outgoing Outro and incoming Intro. It must start no later than the incoming song, and a short liner must not pull that song ahead of its planned Segue. A long liner can delay the song. For example, a ten-second ID over a five-second intro can start the song five seconds into the ID. With no incoming intro, finish the ID before starting the song. Preserve internal pauses.

A positive Overlap start gives an explicit release point for the next song. Start that liner at the outgoing song's Segue with the usual music fade, then start the new song after the specified delay, measured from the liner's selected Start. Any remaining liner audio is allowed over the incoming vocal. Plague therefore releases the next song at 5.3 seconds and keeps its reverb through End at 8.809 seconds. The overlap point does not cut or fade the liner. This single field replaces separate ID, jingle and voice timing rules.

Smooth processing includes the B source preparation and smooth v2 output compressor and limiter. Cache prepared audio so the whole-song leveling happens once, outside live playback. Preserve the original files and their timing. Run the output processor continuously across tracks and overlaps; the browser should monitor that same server output.

The B reference used music at -22 LUFS with slow leveling capped at a 4 dB boost, voice compressed at 3:1 then brought to -17.5 LUFS, the two produced IDs at -19 LUFS, and Plague at -22 LUFS. Keep the 6 dB mixing headroom and reuse those prepared files for the first live comparison. Start new liners with the common 3:1 voice preparation and -17.5 LUFS target, then listen to both raw speech and produced imaging before settling that default. This shared preset will not exactly reproduce the individually prepared IDs and jingle.

Keep output gain fixed after calibration on a continuous programme. The per-excerpt loudness matching used in the audition files is not part of live playback. Stereo Tool can follow as an alternative output processor using the same prepared sources.
